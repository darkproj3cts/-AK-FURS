# Тестовое задание AK Furs — AI-ассистент

Детерминированный анализатор данных ателье-шоурума. Одна команда пересчитывает все ответы из сырых файлов.

## Запуск

```bash
# Установить зависимости
pip install -r requirements.txt

# Получить answers.json (только JSON в stdout, логи в stderr)
python solve.py data/ > answers.json

# Запустить тесты
python -m pytest tests/ -v
```

## Структура репозитория

```
solve.py                  # Решатель — единственный рабочий файл
requirements.txt          # openpyxl, pytest
answers.json              # Эталонный вывод на учебных данных
data/                     # Файлы данных (в .gitignore — не коммитятся)
deliverables/
  memo.txt                # Q5a: служебная записка руководителю
  chat_c0010_reply.txt    # Q5b: варианты ответа менеджера в C0010
docs/
  recon.md                # Разведка: структура файлов, грязь, принятые решения
  ai_mistakes.md          # Ошибки и исправления в ходе работы
tests/
  test_solve.py           # 56 юнит- и интеграционных тестов
debug_q4.txt              # Цитаты из чатов Q4 (автогенерируется solve.py)
```

## Допущения и принятые решения

1. **Формат дат со слешем** (`11/02/2025`) — DD/MM/YYYY. Подтверждено данными: 138 строк с первой частью >12.
2. **Дубли CRM**: пара (номер заказа, № строки) — берём строку с наибольшим `Выгружено`. При совпадении `Выгружено` строки идентичны — берём любую.
3. **Нет записи в прайсе** на дату создания заказа — строка пропускается, пишется в notes. В учебных данных таких случаев нет.
4. **«Все изделия шьём в нашем ателье»** — не приглашение на встречу (Q4).
5. **`Счёт №` в выписке** = номер заказа (173/173 совпадений с CRM).
6. **Артикулы в Прайс_история** хранятся только под новым именем; старые разрешаются через лист «Переименования».
7. **Возвраты в выписке** (тип «Списание») — не поступления, не учитываются в Q2.
8. **Q4, C0010** — менеджер не назвал цену (чат обрывается на вопросе клиента), чат не включён в ответ Q4.
